# PayFlow v0.6.0

Release date: 2026-07-25

## Overview

PayFlow v0.6.0 extends the secured Kafka dead-letter operations control
plane with read-only command-audit investigation workflows.

The release allows authorized operators to search append-only replay and
discard audit records and inspect the chronological timeline of an individual
command without exposing sensitive Kafka or authentication data.

It also modernizes the JavaScript runtimes used by the GitHub Actions CI
workflow while preserving Java 21, Maven caching, test execution, and artifact
upload behavior.

## Highlights

### Command-audit list API

Authorized operators can list audit records with deterministic pagination and
optional filters for:

- command UUID
- operator UUID
- dead-letter record UUID
- command type
- command stage
- command outcome

Results are ordered by `occurredAt DESC, id DESC`.

### Command timeline API

Authorized operators can retrieve the chronological timeline for one command
UUID.

The timeline supports:

- completed commands with `ATTEMPTED` and `COMPLETED` entries
- in-progress or interrupted commands with an `ATTEMPTED` entry only
- deterministic ordering by `occurredAt ASC, id ASC`
- a stable not-found response for unknown command UUIDs

### Security and privacy

Both audit-query endpoints require a bearer JWT that resolves to the
`PAYFLOW_OPERATIONS` authority.

Responses use an explicit safe-field allowlist and never expose:

- Kafka payloads
- Kafka record keys
- JWTs or access tokens
- request headers
- operator email addresses
- exception messages
- stack traces
- replay lease owners

The query boundary is read-only and does not modify the existing append-only
audit trail.

### PostgreSQL query persistence

The release adds a dedicated JDBC query adapter for audit pages and command
timelines.

Queries use bound parameters, fixed predicate allowlists, and deterministic
tie-breakers. User-supplied values are never interpolated into SQL text.

### V13 query indexes

Flyway migration V13 replaces the earlier audit-query indexes with indexes
that include deterministic UUID tie-breakers.

It also adds dedicated support for command-stage and command-outcome filters.

The migration does not change the append-only trigger, table constraints, or
audit-write behavior introduced in v0.5.0.

### OpenAPI and Postman contracts

The OpenAPI public-path contract now includes both audit-query endpoints.

The Postman `Operations` workflow includes:

- command-audit listing
- command-audit timeline retrieval
- optional disabled filters
- safe local environment variables
- response checks for sensitive-field exclusion

Committed privileged tokens and operational UUID values remain empty.

### GitHub Actions runtime modernization

The CI workflow upgrades:

- `actions/checkout` from v4 to v6
- `actions/setup-java` from v4 to v5
- `actions/upload-artifact` from v4 to v7

The pull-request run completed successfully without the previous Node.js 20
runtime deprecation warning.

## Operations API

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/api/v1/operations/kafka/dead-letter-command-audits` | Lists safe, paginated command-audit entries with optional filters. |
| `GET` | `/api/v1/operations/kafka/dead-letter-command-audits/{commandId}` | Returns the chronological timeline for one operator command. |

Both endpoints require a bearer JWT that resolves to `PAYFLOW_OPERATIONS`.

## Compatibility

The v0.6.0 API changes are additive.

No existing public authentication, user, wallet, transfer, transaction
history, or dead-letter administration endpoint is removed or renamed.

## Upgrade notes

1. Back up PostgreSQL according to the deployment environment's normal
   operational procedure.
2. Deploy the application with Flyway enabled so migration V13 is applied.
3. Ensure the trusted JWT issuer grants `role=ADMIN` only to authorized
   operators.
4. Update operator tooling to use the new audit list and timeline endpoints
   when command investigation is required.
5. Do not commit live operator JWTs or operational UUIDs in Postman
   environments.
