# PayFlow v1.0.0

PayFlow v1.0.0 is the first stable-version release candidate of the simulated
digital-wallet backend. The v1 line focuses on release hardening, executable
contract closure, recovery and compatibility verification, supply-chain review,
and clean-environment evidence rather than new product scope.

PayFlow does not process real money and this release does not claim regulatory,
production, availability, capacity, signing, SLSA, or reproducible-build
certification.

## Highlights

### Authentication and security lifecycle closure

- email verification, password recovery, JWT signing-key rotation, MFA, recovery codes, purpose-bound step-up grants, refresh-session revocation, generalized abuse protection, and the separate password-login limiter were re-reviewed for the v1 lifecycle
- current-state security guidance and executable drift contracts were aligned without expanding authentication behavior
- anti-enumeration, credential redaction, trusted-client resolution, digest-only credential persistence, single-use proofs, and fail-closed security boundaries remain intact
- registration remains under the evidence-backed `DEFER` decision and is not activated merely for the v1 version

### Financial and messaging integrity

- wallet ownership, simulated top-up, atomic transfer processing, source-wallet-scoped idempotency, optimistic concurrency, and immutable double-entry ledger behavior remain frozen
- PostgreSQL remains the durable system of record for financial state, transactional outbox records, dead-letter state, replay lineage, and operator audit records
- the focused v1 integrity diagnostic covered 119 transaction/wallet/ledger/outbox/event-processing test classes and 564 tests with zero failures, errors, or skips
- Kafka retry, dead-letter, replay, acknowledgement-ambiguity, and duplicate-processing boundaries remain within the existing idempotent at-least-once design

### Observability and bounded performance evidence

- structured request logging, trustworthy correlation identifiers, centralized sensitive-value masking, bounded metrics, dashboards, and alerts were re-validated
- the repository-approved protected-workflow performance recorder produced fresh accepted developer-workstation evidence for the v1 candidate
- reviewed steady-state, quota/security, overload, and recovery contracts passed; the recorded recovery observation was `0.038` seconds against the documented 30-second budget
- the performance record is local/synthetic evidence and is not a production-capacity claim

### Recovery, migration, API, and documentation freeze

- PostgreSQL backup/isolated-restore, Flyway clean-install, and approved previous-release upgrade procedures were freshly re-validated
- the checked-in migration chain remains V1 through V24; no historical Flyway migration is rewritten for v1
- Redis fail-closed recovery and PostgreSQL-backed Kafka outbox/dead-letter/replay recovery procedures were re-validated without changing runtime retry or durability semantics
- the public `/api/v1` surface remains frozen at 30 canonical method/path operations across 28 normalized paths
- OpenAPI metadata is `1.0.0`; the committed Postman collections remain aligned with the frozen compatibility surface
- no `/api/v2`, DTO redesign, schema expansion, or hidden breaking API change is introduced by the v1 release preparation

### Supply-chain and clean-environment verification

- committed-content secret scanning passed against the reviewed Gitleaks baseline with no new secret location
- fresh dependency/SBOM review reported OSV Critical `0`, High `0`, Medium `6`; the remaining lower-severity findings stay visible rather than being suppressed
- reviewed builder and runtime container paths reported Critical/High `0 / 0`
- no suppression or vulnerability-retuning mechanism was introduced to make the release gate pass
- the clean-environment rehearsal used Java `21.0.2`, Maven Wrapper `3.9.16`, an isolated fresh Maven local repository, and a detached clean checkout
- the complete clean-environment Maven suite passed `1649 / 0 / 0 / 0`
- required production configuration continued to fail fast when deliberately incomplete, and the production-profile Docker smoke contract passed

## Compatibility and security boundaries

- Java 21
- Spring Boot 3.5.16
- PostgreSQL 17 with Flyway migrations V1 through V24
- Maven Wrapper 3.9.16
- frozen `/api/v1`: 30 canonical operations across 28 normalized paths
- OpenAPI version: `1.0.0`
- registration remains `DEFER`
- existing password-login limiter counters, keys, limits, public behavior, and metrics remain unchanged
- existing MFA, JWT rotation, refresh-session, wallet, transfer, ledger, outbox, Kafka, dead-letter, replay, audit, recovery, and observability semantics are not redesigned for version branding

## Release verification

Before the release-preparation candidate is eligible to merge:

- Maven project version must be exact `1.0.0`
- complete Maven verification must pass with zero failures, errors, or skipped tests
- executable `payflow-1.0.0.jar` and its local checksum must be verified
- committed secret, vulnerability, and SBOM gates must have no unresolved Critical/High release blocker
- required production configuration fail-fast behavior must remain intact
- production-profile Docker smoke must pass
- GitHub `CI` and `Docker Smoke` must both succeed on the exact unchanged release-preparation PR head

The real `v1.0.0` annotated tag, tag object, publication workflow run, GitHub
Release ID, published artifact size, and independently verified published
SHA-256 are intentionally not recorded here before immutable publication.

## Explicit non-goals

- new wallet, transfer, payment, authentication, registration, or public API capabilities
- registration activation or login-limiter / abuse-protection retuning without a verified defect
- new MFA factors, OAuth/OIDC, WebAuthn/passkeys, or authenticator redesign
- schema expansion or historical Flyway migration rewrites
- Kafka/outbox/dead-letter/replay topology redesign
- microservice extraction
- Kubernetes, gateway, CDN, WAF, service mesh, or deployment redesign
- artifact signing, SLSA provenance, reproducible-build guarantees, provenance attestation, regulatory certification, production certification, production-capacity guarantees, or real-money operation
